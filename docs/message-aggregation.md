# 消息聚合验收目标

本次实现将原始事件派生为模型调用、工具调用和 Trace 摘要，保留现有 Nuxt 面板与 AgentWorkOverview。表格始终每条 call 一行，不设独立摘要区域或摘要行；一次运行三条 call 占三行，两次占六行。时间轴按 model/tool 共用轨道。点击行内 Trace ID 查看摘要与生命周期；没有调用的失败 Trace 在表格空态提供错误入口。

## 验收标准

表头固定为 TraceID、Name、Agent、Duration、Type、Status、Model、Tokens。Tokens 列展示模型总量；输入与输出分量放在详情和底部汇总。

## 范围

本期记录请求与组装后的最终响应，不增加 delta、工具执行开始、更多提供方完整适配、持久化或跨页面会话。原始事件是唯一事实来源，聚合记录由 core 派生。

## 验证记录

2026-10-28：A1–A9 已由对应单测与现有浏览器预览验证；A10 的完整测试、类型检查、lint 和补丁格式检查均通过。浏览器使用现有的 3000 面板与 4317 Playground 守护进程。

### 自动化

- `pnpm test --run`：16 个文件、114 个用例通过。覆盖协议、SDK、core、worker 接入、面板状态与渲染、时间轴投影和原有组件行为。
- `pnpm -r --parallel --if-present typecheck` 与 `pnpm run typecheck:root`：全部通过，SDK 测试也已纳入类型检查。
- `pnpm lint` 与 `git diff --check`：通过。
- 新增扩展包的 SDK 工作区测试依赖，锁文件通过 `pnpm install --offline --frozen-lockfile --ignore-scripts` 校验；没有新增第三方依赖或更新外部版本。

### 浏览器

- 从真实 Playground 天气流程捕获七个 SDK 消息；两组独立 requestId 正确配对，面板展示两条模型和一条工具调用，Token 为 66/26/92。
- 两次运行得到六个表格行，时间轴仍为 model/tool 两组；工具筛选后两行。无独立摘要区域或摘要行，八列表头与约定一致。
- 六个详情页签有内容；工具参数和结果、Return interval、Trace 生命周期与总区间可查；来源事件搜索、父模型和同 Trace 关系跳转、键盘导航与时间轴缩放验证通过。
- 显式 ID 与旧事件结果先到、输入后到，在存在另一条调用时保持选中调用和 Raw Events 页签；真实滚动位置保持在 100。
- 无目标 Trace 错误保留 interrupted 调用与原错误；没有调用的失败 Trace 不生成调用行，通过表格空态查看错误。
- 含 img/script 的 payload 仅显示为文本，没有生成可执行节点；验收页面没有 error/warn 控制台消息。

浏览器面板使用受控 Chrome Port 替身注入快照和增量；SDK 消息来自真实页面运行。另有集成单测将真实 SDK 消息送入 worker 验证、广播及重连快照后再聚合。以上不等同于已安装 Chrome 扩展的端到端验收，也不包含生产打包验收。按用户要求没有启动 dev 或主动运行 build；早期根 typecheck 曾因 Turbo 配置连带执行依赖构建，发现后已改用上述直接检查命令。

### 消融与简化

1. 沿用现有 AgentWorkOverview，移除旧时间轴、Trace 分组/折叠和额外摘要区域；相同七事件与双运行输入分别得到三行与六行，筛选、统计和导航一致。
2. 移除来源事件选择锚点，运行 `another call precedes` 用例：旧事件补齐输入后误选较早的其他调用，断言从 legacy question 变成 other 而失败。恢复后完整测试通过，因此保留锚点。早期同时间戳样例未暴露问题，已改为独立时间验证，避免偶然排序掩盖缺陷。
3. 详情滚动容器使用默认自动锚定时，相同输入从 scrollTop 100 跳到 339；禁用 overflow-anchor 后，显式与旧数据均保持 100。因此保留该浏览器行为约束。
4. 保留严格协议边界、显式关联和冲突原始信息；不引入独立的可变调用账本。聚合结果统一来自 core，时间轴投影只负责展示。
